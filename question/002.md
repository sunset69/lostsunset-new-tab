# 问题
1. 搜索引擎使用关键字切换后就无法切换了


# 改善
1. 左上角下拉框选择样式美化一下
2. 分组要可以快速添加

# 解决方式
## 问题
1. 根因：[SearchBar.tsx](../src/newtab/components/SearchBar/SearchBar.tsx) 的临时引擎态是「对象 + `overrideEngine === null` 一次性守卫」——keyword 触发后：①守卫导致第二个 keyword（如再输 `bing `）永远无法触发；②清空输入框也不复位，徽标卡在临时引擎，只能靠下拉菜单逃脱。修复：临时引擎收敛为单一稳定 id（`overrideEngineId`），候选列表每按一次键都基于当前生效引擎实时计算——清空输入立即复位默认引擎；keyword 可连续切换（`baidu␣`→`bing␣` 即回 Bing）；命中默认引擎直接落回 null 而非挂等价临时态；下拉菜单 `aria-selected` 跟随当前生效引擎，徽标在临时态显示青色圆点与「·临时」文案及提示 title。提交后仍恢复默认引擎（不落盘）。

## 改善
1. [EnvironmentSwitcher.tsx](../src/newtab/components/EnvironmentSwitcher/EnvironmentSwitcher.tsx) 由原生 `<select>` 重构为自定义 listbox：玻璃拟态渐变 chip（彩色环境圆点带光晕、内高光、按压态、chevron 展开旋转）+ 深色圆角菜单（彩色圆点、当前项青色高亮与对勾）。完整保留无障碍：`aria-haspopup/expanded`、`role=listbox/option`、方向键/Home/End/Enter/Escape、首字符跳转、Tab/焦点移出自动关闭、选择后焦点归还 chip；`prefers-reduced-motion` 关闭动画。
2. [ShortcutQuickAdd.tsx](../src/newtab/components/ShortcutQuickAdd/ShortcutQuickAdd.tsx) 分组下拉新增「＋ 新建分组…」：选中后在弹窗内内联展开名称输入（Enter 确认/Esc 仅退出建组不关弹窗），空名称与重名行内报错；确认后经 `createShortcutGroupDraft`（order 接续 max+1）入库并自动选中，新分组在 Dock 筛选 tab 中即时出现；提交快捷方式即落入新分组。此前应用内没有任何建组入口，只能靠备份导入。

验证：244 个单测（新增 keyword 锁死回归 5 例、环境切换器键盘/焦点 6 例、快速建组 4 例）+ typecheck 0 错误 + build 全绿；chrome-devtools MCP 真实键盘走查：`baidu␣` 临时态→清空复位→`bing␣` 切回→菜单高亮/选择→真实跳转 `https://www.baidu.com/s?wd=%E5%A4%A9%E6%B0%94`；环境 chip 鼠标+键盘切换并持久化；弹窗建组「工作」并添加 work.example.com 后 tab 筛选正确；控制台仅 work.example.com 的 favicon 预期网络错误（回退首字母）。
